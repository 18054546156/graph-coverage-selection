这些分数到底说明什么？

这是一份给非专业读者的指标说明。每个指标都按“它在问什么、怎么算、例子是多少、应该怎么判断”解释。示例数字都是虚构教学数据，不是实验实测结果。

先记住比较顺序：先看 clean BA 的绝对值，再看 corruption BA；然后看 BA drop、最差类别和置信度指标。不要只看一个平均数，也不要只看下降幅度。

一、分类性能

回答模型“答对了多少”，是主结果。

越高越好
ACC
普通准确率

所有图片中答对的比例。

ACC = 答对的图片数 / 全部图片数
Recall_c
类别 c 的召回率

真实属于类别 c 的图片，有多少被认出来。

Recall_c = 类别 c 答对数 / 类别 c 总数
BA
Balanced Accuracy

先算每个类别的 Recall，再等权平均。

BA = (Recall_1 + ... + Recall_C) / C
Worst recall
最差类别召回率

所有类别中最低的那个 Recall。

Worst recall = min(Recall_1, ..., Recall_C)
虚构例子：为什么 ACC 会骗人

测试集有 90 张甲类、10 张乙类。模型把 100 张全部猜成甲类。

ACC = 90 / 100 = 90%
Recall_甲 = 90 / 90 = 100%
Recall_乙 = 0 / 10 = 0%
BA = (100% + 0%) / 2 = 50%

读法：ACC 看起来很高，但模型完全不会识别乙类。BA 把两个类别等权后揭示了这个问题。

一个简单的检查方法

ACC 90%
BA 50%
Worst 0%

如果 ACC 和 BA 差很多，优先查看每类 Recall，而不是继续看 ACC。

二、干扰鲁棒性

回答图片被污染后，模型还剩多少识别能力。

绝对值优先
Corruption BA

在某一种 corruption、某个 severity 下重新计算 BA。

Corruption BA = 干扰测试集上的各类 Recall 平均
BA drop

clean BA 减去 corruption BA，单位通常是百分点 pp。

BA drop = clean BA - corruption BA
Worst recall drop

看最差类别在干扰下又掉了多少。

drop = clean worst recall - corrupt worst recall
Per severity

分别看 severity 1 到 5，不能只看一个总平均。

每种 corruption × 每个 severity 单独计算
虚构例子：下降小不等于模型强
模型Clean BACorruption BABA drop正确解读
模型 A90%70%20pp绝对能力较强，但干扰后损失较大
模型 B65%60%5pp下降较小，但绝对能力仍明显较弱

结论：不能只按 BA drop 排名，必须同时看 clean BA 和 corruption BA。

三、概率质量：模型说“我确定”可信吗？

分类答对不等于概率可信。这里的指标通常越低越好。

越低越好
NLL

真实类别拿到的概率越高，NLL 越低。模型“很自信但答错”会被重罚。

NLL = - 平均 log(p_true)
Brier

整个概率向量与正确 one-hot 向量的平方距离。

Brier = 平均 Σ_c (p_c - onehot_c)²
ECE15

把 confidence 分成 15 个等宽区间，比较每个区间的平均 confidence 和真实准确率。

ECE = Σ_b (N_b/N) × |accuracy_b - confidence_b|
NLL 和 Brier 单张图片例子

真实类别是甲，模型输出：

p = [甲: 0.80, 乙: 0.15, 丙: 0.05]
NLL = -ln(0.80) ≈ 0.223
Brier = (0.80-1)² + 0.15² + 0.05² = 0.065

真实类别概率从 0.80 降到 0.01 时，NLL 会大幅变差。

ECE15 例子

假设只有两个 confidence bin：

Bin 1：5 张，confidence=0.90，实际准确率=1.00
Bin 2：5 张，confidence=0.60，实际准确率=0.40
ECE = (5/10)|1.00-0.90| + (5/10)|0.40-0.60| = 0.15

模型整体平均误差为 15 个百分点。当前项目是 15-bin top-label ECE，不能和不同 bin 规则的 ECE 直接混比。

四、选择性预测：不确定时能不能拒答？

模型不是必须回答所有图片，可以只接受最有把握的一部分。

越低越好
Risk@80

按 confidence 排序，只接受最有把握的 80% 后，这些已接受预测中的错误率。

Risk@80 = accepted 部分的错误数 / accepted 数
AURC

逐渐放宽接受范围，画 coverage-risk 曲线，再计算曲线下面积。

AURC = 平均_k [前 k 个样本的累计错误率]
High-conf errors

confidence 达到阈值却预测错误的数量。是危险的“自信错误”。

count(confidence ≥ 0.8 且预测错误)
Coverage

系统实际接受了多少预测。Risk 低但 coverage 极低，实用价值可能有限。

Coverage = accepted 数 / 全部样本数
Risk@80 和 AURC 例子

测试集有 10 张图，按 confidence 从高到低排列。接受前 8 张，其中 2 张答错：

Risk@80 = 2 / 8 = 25%

如果模型能把错误都排到列表后面，那么 AURC 会低；如果高置信度位置就出现很多错误，AURC 会高。

注意：Risk@80 的 80 指接受比例，不是“confidence 大于 80%”。

五、选集稳定性和可复现性

这些指标不直接评价模型，而是检查“每次到底选了什么”。

不是越高越好

Jaccard：两次选集重合多少？

J(A,B) = |A∩B| / |A∪B|

例子：A 选了 5 张，B 选了 4 张，共有 3 张重合。

J = 3 / (5 + 4 - 3) = 3/6 = 0.50

1.0 表示完全相同，接近 0 表示几乎没有重合。

SHA256、类别计数和选样数量

  • selection_size：有没有真的选够 2% 或 5%。
  • class_counts：类别配额是否正确。
  • index_order_sha256：选中的 ID 及顺序是否完全一致。
  • checkpoint_sha256：保存的模型文件是否被替换。
当前诊断的例子：Random 的不同 selection seed 选集几乎完全不同；Graph-A2 的 Jaccard=1，说明当前实现下 selection seed 没有改变 Graph-A2 选集。

六、训练过程审计指标

用来判断“结果不同是方法不同，还是训练根本没对齐”。

解释差异
指标它检查什么看到异常时先查什么
train_loss模型是否在学习训练集输入、标签、学习率、loss 实现
train_accuracy训练集上的拟合程度过拟合、类别不平衡、选集质量
learning ratescheduler 是否按预定方式变化step 时机、总 epoch、iteration/epoch 混淆
optimizer updates实际参数更新次数是否一致batch 数、drop_last、数据量、训练轮数
initial weight hash两个入口是否从同一个初始模型开始seed 设置顺序、预训练权重、初始化调用
prediction hash最终预测是否确实来自该 checkpointcheckpoint 加载、test transform、标签顺序
重要：只有 final.pt，没有完整的 metrics.jsonl、预测文件和完成标记，不能计算有效的 BA 方差，也不能作为一次完成的实验。

七、最终结果应该怎么汇报？

一张主表回答性能，附表解释原因。

推荐格式

每个数据集、每个方法至少报告

  1. clean BA：主指标
  2. ACC 和每类 Recall
  3. Worst-class recall
  4. corruption BA 和 BA drop
  5. NLL、Brier、ECE15
  6. Risk@80、AURC
  7. 多个 seed 的 mean、sample SD、95% CI

Graph-A2 与 Random 应该如何比较

ΔBA(seed) = BA_Graph-A2(seed) - BA_Random(seed)

不要只找 Graph-A2 赢的 seed。应在相同数据集、相同 training seed 下做配对差值，再报告：

  • 平均 ΔBA
  • ΔBA 的标准差
  • 95% 置信区间
  • Graph-A2 胜出的 seed 数量
一句话总结：BA 说明“各类平均答对多少”，worst recall 说明“最差类有没有被掩盖”，corruption BA 说明“受干扰后还剩多少能力”，ECE/NLL/Brier 说明“置信度是否可信”，Risk/AURC 说明“能不能把危险预测筛出来”，Jaccard 和 hash 说明“选集是否真的可复现”。
本页示例数字均为教学示例。当前项目的正式比较仍以固定 commit、固定数据缓存、明确的 selection/training seed 和完整产物校验为准。
